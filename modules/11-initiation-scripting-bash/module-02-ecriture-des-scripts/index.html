    Page 2

    Écriture des scripts

    • Les scripts Shell sont des fichiers texte dans lesquels sont stockées des suites de commandes. Ces fichiers peuvent être créés et modifiés par l’éditeur de texte vim.
    • Lors de l’interprétation du script par le Shell, les commandes sont lues et interprétées séquentiellement.
    • Une ligne de commentaire commence par le caractère #. Ce même caractère peut être placé derrière le dernier élément d’une ligne à condition qu’il soit précédé d’au moins un espace.

    Écriture des scripts

    Le shebang

    Afin d’éviter des erreurs, il est conseillé de spécifier

    $ vi monscript.sh

    le Shell à utiliser grâce au shebang.

    #!/bin/bash
    • Il doit être écrit sur la première ligne du script.
    echo Hello world
    • Il est matérialisé au moyen de la chaîne #! suivie du chemin du Shell à utiliser (exemple : #!/bin/bash).
    • Il est possible d’indiquer le SH, le KSH, le Python, le Perl, ou tout autre langage interprété.
    • S’assurer du chemin spécifié, en utilisant par exemple la commande which.

    Page 3

    Écriture des scripts

    Commenter

    • Il est important de commenter ses scripts, afin de :
    • Rendre les modifications a posteriori plus simples.
    • Les rendre plus compréhensibles pour d’autres personnes.
    • Tout texte inséré après le signe dièse (#) ne sera pas interprété.
    $ vi monscript.sh
#!/bin/bash
# ce script affiche la phrase « Hello World ! »
echo Hello world !
    # on peut commenter après une instruction

    Écriture des scripts

    Commenter

    • L’affectation d’un entête de script complet fait partie des bonnes pratiques.

    Page 4

    Écriture des scripts

    Fichier exécutable

    Il faudra affecter la permission execute pour rendre le script exécutable.

    $ chmod +x ./monscript.sh
    $ chmod ug+x ./monscript.sh

    Écriture des scripts

    Débuguer

    Les erreurs dans les scripts ne sont pas toujours faciles à repérer. Plusieurs méthodes peuvent être utilisées afin de les identifier.

    • L’exécution du script en mode trace permet d’exécuter une à une les commandes de celui-ci tout en les affichant précédées du signal plus (+).
    $ bash -x monscript.sh
+ echo Hello world
Hello world

    Page 5

    Écriture des scripts

    Débuguer

    • L’intégration dans le script de commandes de débogue se traduit par l’ajout temporaire de commandes permettant d’analyser une situation.
    echo "tapez votre nom"
read nom
## echo de debug avec pause :
echo "valeur de la variable nom : $nom"
read
           # pause avant de poursuivre le déroulement du script
## fin du debug
echo "Bienvenue $nom sur la machine $HOSTNAME"
    • Cela permet de contrôler le résultat d’exécution de certaines parties du script et d’identifier des sources potentielles de dysfonctionnement.

    Écriture des scripts

    Débuguer

    • Les commandes de débogue doivent être commentées avant la mise en production :
    echo "tapez votre nom"
read nom
## echo de debug avec pause :
#echo "valeur de la variable nom : $nom"
#read
## fin du debug
echo "Bienvenue $nom sur la machine $HOSTNAME"

    Créez un fichier texte à partir de l’algorithme, choisissez son interpréteur et contrôlez les résultats. Le support utilise Bash et l’éditeur vi ou vim.

    Interpréteur, commentaires et permissions¶

    Ouvrez monscript.sh avec vi monscript.sh. Placez le shebang en première ligne. Documentez le rôle du script avec #. Un en-tête peut donner son usage, ses dépendances et sa version.

    #!/bin/bash
# Afficher un premier message sur la console.
echo "Hello world"

    Le suffixe .sh identifie le fichier pour le lecteur. La permission d’exécution et le shebang servent au lancement direct. Le support montre which bash pour rechercher l’interpréteur. command -v bash permet aussi de voir comment le shell résout ce nom.

    Forme Effet
    bash monscript.sh Bash lit le fichier indiqué
    chmod u+x ./monscript.sh Ajoute l’exécution au propriétaire
    chmod ug+x ./monscript.sh Ajoute l’exécution au propriétaire et au groupe
    ./monscript.sh Lance le fichier selon son shebang

    Le support présente aussi chmod +x ./monscript.sh. Enregistrez le texte avec des fins de ligne Unix LF pour que le shebang soit interprété correctement.

    Identifier une erreur¶

    bash -n monscript.sh

    Complément pédagogique. bash -n contrôle la syntaxe sans exécuter les commandes. Ce contrôle précède un essai en laboratoire. Dans le support, bash -x monscript.sh exécute le script et affiche les commandes après développement des arguments. Examinez les valeurs sur des données de test et gardez les secrets hors de la trace. Options de Bash

    Le support ajoute aussi temporairement un affichage et un read pour faire une pause. Voici un exemple où le diagnostic passe par la sortie d’erreur.

    #!/bin/bash
read -r -p "Tapez votre nom : " nom || exit 1
printf 'Diagnostic — nom reçu : %s\n' "$nom" >&2
read -r -p "Appuyez sur Entrée pour poursuivre. " pause
printf 'Bienvenue %s sur la machine %s\n' "$nom" "$HOSTNAME"

    Retirez les pauses de diagnostic avant un lancement automatisé. Conservez les messages qui permettent à l’appelant de comprendre une erreur.
