# Atelier n°4 — Gestion réseau d’une infrastructure vSphere

Durée source : **une heure**. Objectif : gérer les réseaux des ESXi. Prérequis :
avoir réalisé l’atelier n°3, avec deux hyperviseurs ESXi fonctionnels.

## Préparer les cartes

Dans VMware Workstation, arrêter proprement les deux hyperviseurs, leur ajouter
chacun trois cartes réseau bridgées, puis démarrer le premier hôte. Ils disposent
ainsi de quatre cartes. L’énoncé vise la séparation des flux de gestion, des VM et
du stockage ; il n’impose pas de nouveaux identifiants VLAN.

!!! warning "NEEDS_REVIEW — arrêt propre"

    La solution montre une option de terminaison forcée des VM. Cette option
    contredit l’arrêt propre demandé et n’est pas une étape normale à reproduire.
    Les changements d’accès réseau et les arrêts concernent uniquement le laboratoire.

## Configurer le premier hôte

Sur le commutateur de gestion existant, ne conserver à terme que le groupe de
gestion, et le renommer avec un nom de laboratoire. Les noms des groupes ci-dessous
sont neutralisés ; les identifiants `vmnic` désignent les cartes techniques du schéma.

| Usage | Type de groupe | Cartes du scénario | Adresse |
| --- | --- | --- | --- |
| Gestion, commutateur existant | VMkernel existant | vmnic0 | Adresse de gestion déjà configurée |
| VM, nouveau commutateur | Machines virtuelles | vmnic1 et vmnic2 | Pas d’adresse VMkernel demandée |
| Stockage/vMotion, autre commutateur | VMkernel | vmnic3 | `<adresse-de-laboratoire>` sur le réseau /24 prévu |

1. Créer le commutateur dédié aux VM avec ses deux liaisons montantes.
2. Lui associer le groupe de ports des VM `<groupe-vm-de-laboratoire>`.
3. Créer le commutateur de stockage/vMotion avec la dernière carte.
4. Lui associer l’interface VMkernel `<groupe-stockage-de-laboratoire>` et son
   adresse de laboratoire. La solution détaille le service vMotion coché.
5. **Ne pas modifier les identifiants VLAN**, conformément à l’énoncé.

La solution précise que la VM invitée utilise encore l’ancien groupe de ports des
VM : déplacer sa vNIC vers le nouveau groupe avant de retirer l’ancien. Ne pas
supprimer le groupe qui porte l’accès de gestion.

## Reproduire sur le second hôte

Reproduire les modifications sur le second ESXi. Utiliser une autre adresse
VMkernel dans le même réseau /24 de laboratoire ; les valeurs réelles sont à
fournir dans cet environnement et ne sont pas publiées ici.

Le travail demandé organise les réseaux ; il ne configure pas encore un stockage
iSCSI complet et n’exécute pas de migration vMotion. Aucun test supplémentaire
n’est inventé à partir du schéma final.
