# Atelier n°3 — Découverte de vSphere

Durée source : **une heure**. Objectifs : installer deux hyperviseurs VMware ESXi
et configurer leur accès. Prérequis : cours du module 5 et VMware Workstation 16.

## Environnement du laboratoire

Le scénario utilise Workstation pour simuler deux serveurs physiques capables
d’héberger des VM. Les ISO ESXi et Windows Server 2019 doivent être fournis dans le
cadre du laboratoire : ils ne sont pas joints aux PDF. L’énoncé mentionne ESXi
7.0 U3, build 18644231. Cette référence historique n’est pas une recommandation
de téléchargement ou de version actuelle.

Les noms ci-dessous sont des repères neutralisés. Adapter les emplacements au
laboratoire autorisé ; aucun chemin interne ou identifiant réel n’est reproduit.

## 1. Préparer les deux hyperviseurs

1. Éteindre la VM Windows Server préparée précédemment, inutilisée dans cet atelier.
2. Créer le premier hyperviseur de type ESXi 7 dans `<chemin-de-laboratoire>`.
3. Lui affecter deux CPU d’un cœur, **6 Go de RAM selon le texte**, une carte réseau
   bridgée, un disque de 40 Go et un disque supplémentaire SCSI de 200 Go.
4. Associer l’image ESXi `<iso-de-laboratoire>`.
5. Installer ESXi sur le disque de **40 Go** ; choisir la langue française et définir
   le secret du compte d’administration conformément aux exigences de complexité.
6. Relever l’adresse obtenue `<adresse-de-laboratoire>` puis laisser la console
   locale en l’état. L’énoncé ne demande pas encore de la configurer.
7. Créer le second hyperviseur avec les mêmes caractéristiques, dans son propre
   emplacement. Son nom, son stockage et son adresse seront distincts.

!!! warning "NEEDS_REVIEW — mémoire et disques"

    Les deux schémas indiquent 8 Go par hyperviseur, contre 6 Go dans le texte.
    Faire arbitrer cet écart avant l’exécution. L’installation initialise son
    disque cible : identifier le disque de 40 Go, distinct du disque de 200 Go.

## 2. Accéder au premier hyperviseur

Depuis l’hôte Windows, ouvrir sa console web dans un navigateur avec l’adresse
relevée et les identifiants définis lors de l’installation. Le schéma de la source
mentionne HTTP ; la solution montre un avertissement de certificat. Cette
observation historique ne vaut pas consigne de contournement : faire vérifier
l’identité de l’hôte et le contexte du certificat dans le laboratoire.

## 3. Préparer le stockage et la VM invitée

1. Dans Stockage, créer une banque de données VMFS sur le disque supplémentaire
   de **200 Go**, en utilisant tout son espace. Employer un nom de laboratoire,
   ici `<stockage-de-laboratoire>`. Cette initialisation concerne ce disque cible.
2. Ouvrir le navigateur de cette banque et y charger l’ISO Windows Server 2019.
3. Depuis Machines virtuelles, créer `<vm-de-laboratoire>` : un CPU d’un cœur,
   2 Go de RAM, un disque de 32 Go et un lecteur CD/DVD utilisant l’ISO de la banque.
4. Mettre la VM sous tension, ouvrir sa console et installer Windows Server 2019.
5. Installer les VMware Tools dans cette VM.

Le résultat demandé est constitué de deux hyperviseurs ESXi, dont l’un héberge
une VM Windows Server fonctionnelle. Aucun test supplémentaire n’est inventé.
