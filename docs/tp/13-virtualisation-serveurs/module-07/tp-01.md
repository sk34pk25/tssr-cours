# Atelier n°5 — Gestion du stockage d’une infrastructure vSphere

Durée source : **deux à trois heures**. Objectifs : mettre en œuvre NFS et iSCSI,
gérer des banques de données. Prérequis : deux ESXi fonctionnels, leur réseau
configuré aux ateliers 3 et 4, et la VM Windows Server 2019 de l’atelier 1.

## Préparer le serveur de stockage

1. Revenir au snapshot de fin d’atelier 1 de la VM Windows Server. Cette opération
   remplace son état courant par celui du snapshot : elle concerne le laboratoire.
2. Démarrer cette VM, qui fournira une cible iSCSI et un partage NFS.
3. Configurer son interface en IPv4 statique sur le réseau /24 de laboratoire,
   avec une adresse distincte de celles des interfaces VMkernel des ESXi.
4. Contrôler la connectivité avec chacun des deux VMkernel au moyen de `ping`.
   Les destinations de la source sont remplacées ici par les adresses du laboratoire.

Exemples neutralisés des seules commandes de contrôle demandées :

```text
ping <adresse-vmkernel-premier-hote>
ping <adresse-vmkernel-second-hote>
```

Ces paramètres sont à remplacer dans le laboratoire autorisé, pas à exécuter tels quels.

## Partie I — iSCSI, accès en mode bloc

### Premier ESXi

Dans Stockage, activer l’adaptateur iSCSI logiciel. Le lier au groupe VMkernel
de stockage/vMotion préparé précédemment et ajouter l’adresse du serveur Windows
comme cible dynamique. L’adresse est neutralisée en `<adresse-serveur-de-laboratoire>`.

### Serveur Windows

1. Ajouter un deuxième disque de **150 Go**, le formater et créer un volume de stockage.
2. Dans ce volume, créer l’arborescence de laboratoire avec un dossier pour les
   banques et un sous-dossier iSCSI, ici `<chemin-iscsi-de-laboratoire>`.
3. Ajouter le service de rôle **Serveur cible iSCSI**.
4. Dans le Gestionnaire de serveur, créer un disque virtuel iSCSI de **80 Go**
   et l’associer à une nouvelle cible. Le texte appelle cet ensemble « cible de
   80 Go » ; la solution distingue le disque virtuel de la cible.
5. Autoriser les deux initiateurs ESXi par leurs adresses de laboratoire.

La solution conserve les autres réglages par défaut dans son scénario ; elle
montre l’absence de CHAP côté ESXi. Ces réglages documentent ce laboratoire et
ne définissent pas une politique d’authentification générale.

### Banques de données

1. Valider l’adaptateur du premier ESXi et réanalyser les adaptateurs de stockage.
2. Vérifier l’apparition du périphérique **MSFT iSCSI** et l’état connecté côté Windows.
3. Sur ce LUN de laboratoire, créer une banque **VMFS** utilisant tout son espace.
   L’initialisation concerne le disque partagé de 80 Go : identifier la cible avant
   formatage. Employer un nom de banque propre au laboratoire.
4. Configurer l’adaptateur logiciel du second ESXi vers la même cible, puis vérifier
   que la banque existante est accessible. **Le texte ne demande pas de reformater
   le LUN depuis le second hôte.**

## Partie II — NFS, accès en mode fichier

Sur Windows Server, créer un autre sous-dossier pour NFS dans le volume de
stockage et ajouter le service de rôle **Serveur pour NFS**. Créer le partage avec
les paramètres historiques de l’énoncé :

- absence d’authentification serveur ;
- accès des utilisateurs non mappés ;
- autorisation des deux ESXi par leurs adresses, en lecture et écriture ;
- **NFS 3**.

!!! warning "NEEDS_REVIEW — permissions du laboratoire"

    Ces paramètres permissifs sont ceux de l’atelier. Ils ne constituent pas une
    recommandation pour un partage de production et doivent être revus dans leur
    contexte avant exécution. Aucun partage n’est créé par cette ingestion.

Sur chaque ESXi, créer une banque de type **Montage NFS** pointant vers le serveur
et le partage de laboratoire. Constater son apparition dans l’inventaire.
