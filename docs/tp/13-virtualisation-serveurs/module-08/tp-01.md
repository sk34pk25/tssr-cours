# Atelier n°6 — Export et import de modèles OVF

Durée source : **une heure**. Objectif : exporter puis importer une VM entre
deux hyperviseurs. Prérequis : deux ESXi et la VM invitée du premier hôte préparée
à l’atelier n°3. La banque iSCSI demandée pour l’import suppose aussi le stockage
préparé dans l’atelier n°5 ; cette dépendance figure dans le corps de l’énoncé.

## Export depuis le premier ESXi

1. Ouvrir son interface web dans le navigateur.
2. Dans Machines virtuelles, sélectionner la VM source et l’action **Exporter**.
3. Dans la boîte de dialogue, conserver les éléments proposés sauf le fichier
   **`.nvram`**, selon la consigne source.
4. Laisser le navigateur télécharger les fichiers localement. Observer les fichiers
   **`.mf`**, **`.ovf`** et **`.vmdk`** dans `<chemin-export-de-laboratoire>`.

Les fichiers VM exportés contiennent des données du laboratoire : ils ne sont
ni fournis par les PDF ni publiés par cette adaptation.

## Import sur le second ESXi

1. Ouvrir son interface web et choisir **Créer/Enregistrer une machine virtuelle**.
2. Choisir le déploiement à partir d’un fichier OVF/OVA, puis les fichiers de
   l’export. La solution sélectionne le descripteur OVF et le disque VMDK.
3. Donner un nouveau nom de laboratoire à la VM et sélectionner la banque iSCSI
   partagée préparée précédemment, `<stockage-iscsi-de-laboratoire>`.
4. Examiner le récapitulatif puis suivre l’avancement dans **Tâches récentes**.
5. À l’issue de l’import, constater la nouvelle VM dans l’inventaire et la démarrer
   pour contrôler son fonctionnement, conformément à l’énoncé.

!!! warning "NEEDS_REVIEW — erreur montrée par la solution"

    La solution affiche une erreur d’image disque requise manquante et demande
    pourtant de poursuivre. Elle n’en fournit pas la cause. Cette indication
    n’est pas une consigne validée de contournement : faire examiner l’erreur
    avant de considérer l’import comme complet. Aucun correctif externe n’est inventé.
