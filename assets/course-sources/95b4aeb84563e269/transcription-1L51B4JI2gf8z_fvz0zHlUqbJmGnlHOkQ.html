Where-Object

Démonstration 05 du module 3

L’objectif de cette démonstration est de présenter la commande Where-Object.

Déroulement

Une des commandes les plus utilisées permet d’appliquer une ou plusieurs conditions sur une ou
plusieurs propriétés d’un objet.

Le conditionnement permet de définir des listes d’objets précises et de pouvoir obtenir un résultat
correspondant au besoin exprimé. 

• 
La commande Where-Object s’utilise en complément de la commande Select-Object

•
Dans un premier temps, nous allons voir une condition simple.

La commande utilisée permet de chercher un ou plusieurs utilisateurs dans la base de données
Active Directory. 

La condition Where-Object permet de trouver le ou les objets utilisateurs pour laquelle la propriété 
Name est égale à Oneal. 
La condition Where-Object utilise les opérateurs de comparaison ici le -eq indique l’égalité.

Nous allons voir qu’il est possible de tester une propriété sans connaître le contenu exact.

Pour cela, on utilise l’opérateur de comparaison Like avec le caractère  * , ce qui nous permet 
d’obtenir tous les utilisateurs dont le nom débute par Ro. 
o Pour rappel, les opérateurs de comparaison par défaut sont insensibles à la

casse. 

o Pour les rendre sensibles à la casse, il faut les préfixer par un c. 
La commande Where-Object est également utilisable sur des propriétés de type booléen. 
Dans ce cas, la propriété est comparée à la variable $True ou $False selon si l’on souhaite tester 
la validation ou non.

Dans le cas de notre commande, on affiche uniquement les comptes Active Directory actifs. 

Where-Object permet également d’utiliser les opérateurs logiques and et or. 
Dans ce cas, il faut vérifier plusieurs propriétés. On se sert de la variable réservée $PSItem vu 
précédemment.

On utilise le paramètre FisterScript indiqué par l’utilisation des accolades de la commande 
Where-Object puis, on utilise la variable réservée $PSItem suivie d’un point puis le nom de la 
propriété à tester.

Le test est ensuite répété sur la seconde propriété ; entre les deux on place l’opérateur logique. 

Dans le cas d’un And, les deux propriétés doivent répondre « vrai » à la condition pour que l’objet 
soit affiché dans le résultat. 
Dans notre test, il faut que l’utilisateur « Active Directory » soit actif et que son nom commence par 
un R. 
Voyons maintenant le cas d’un Or.
